# Visual identity sheet

Scope: docs/visual-identity.html, a static reference page. Mode: Read, showing Operate components.

Audience: the owner and anyone building apps/web. Job: see every token and component in its states, in both themes, and copy the rule. Content: docs/branding.md. Constraint: sample data only, labelled; no invented figures about the product.

Memorable moment: the at-risk positions table at the top, advancing one block on request.

Unresolved: risk thresholds are placeholders; chart palette untested in a real chart.

## Direction contract

THESIS: The sheet opens on the product's own object working, the at-risk positions table, and refuses the brand-book order of logo, swatch grid, font specimen.

OWN-WORLD: warm near-black ground, panels one step lighter with a hairline, one violet accent kept for action and selection, three status colours kept for status, tabular figures, and a small stamp of block and age under every reading.

STORY: the reader sees what the tool looks like in use, then the tokens that make it, then each component in every state, then how it speaks.

FIRST VIEWPORT: a 220px rail of section links on the left under the wordmark; on the right a 24px title, one sentence, and the positions table at full width with health badges, a block stamp, and one button that advances a block.

FORM: reference sheet with a sticky rail. seed: none (pinned) "Create an html as the visual-identity and create all the components and how will they look." and, for the world: "make it using the same aave branding primitives, colors and public fonts, without using their logos" and "Yes, dark default".

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
